AWS KMS cluster rotation scenarios

One key per cluster means one physical KMS key for each signing slot, shared by every SPIRE server. Old and replacement keys can both exist while a rotation is in progress, but only one key is active for each authority type. This page covers startup, rotation, recovery, migration, and cleanup.

The account, ARNs, UUIDs, timestamps, and authority IDs below are complete example values. They are not values from a production environment.

CA journal and public keys

The CA journal is the shared database record for current and prepared CAs. SPIRE saves it before loading a signer. The ARN column shows the KMS key used for signing; the journal stores the public key or certificate, not the ARN.
